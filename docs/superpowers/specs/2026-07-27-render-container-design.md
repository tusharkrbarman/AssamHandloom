# Render Container Deployment Design

## Goal

Deploy the existing Luit & Loom FastAPI catalogue preview to Render as a
containerized web service backed by Render PostgreSQL.

## Scope

This deployment exposes the existing read-only, twelve-product sample
catalogue. It does not add checkout, payments, customer accounts, inventory
management, or order management.

## Architecture

Render builds one Docker image from the repository. A Render Blueprint creates
one free web service and one free PostgreSQL database in the Singapore region.
The web service receives the database connection through Render's private
network and generates its application secret through Render.

The container startup command applies Alembic migrations, runs the existing
idempotent sample-catalogue loader, and then starts Uvicorn on Render's `PORT`.
This startup sequence is used because Render's separate pre-deploy command is
not available on free web services.

## Configuration

- Production runs with `ENVIRONMENT=production`.
- `CATALOGUE_PREVIEW_ENABLED=true` keeps the bundled sample catalogue visible.
- `DATABASE_URL` accepts Render's `postgresql://` connection string and
  normalizes it to the installed async Psycopg driver.
- `PUBLIC_BASE_URL` uses Render's automatically supplied external URL.
- `SECRET_KEY` is generated by Render and is never committed.
- The web service binds to `0.0.0.0` and Render's runtime `PORT`.

## Health and Failure Behavior

Render checks `/health/ready`, which succeeds only when PostgreSQL accepts a
query. A failed migration or seed exits the container before Uvicorn starts, so
Render does not publish a partially initialized deployment. The existing seed
operation is idempotent, allowing safe restarts for this single-instance demo.

## Files

- `Dockerfile`: reproducible Python 3.12 runtime and startup command.
- `.dockerignore`: excludes local, Git, test, and cache files from the image.
- `render.yaml`: free Render web service, free PostgreSQL database, environment
  references, and health check.
- `app/config.py`: Render database URL normalization and public URL fallback.
- `tests/integration/test_health.py`: focused configuration compatibility tests.
- `README.md`: local container check and Render Blueprint deployment steps.

## Verification

The change must pass the focused configuration tests, the complete PostgreSQL
test suite, Ruff, mypy, and a Docker image build. The built image must start
against PostgreSQL, migrate and seed successfully, and return HTTP 200 from
`/health/ready` and the storefront home page.
